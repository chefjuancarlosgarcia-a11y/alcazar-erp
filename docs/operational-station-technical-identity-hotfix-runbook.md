# Hotfix: operational station technical identity (196 + FE + Edge)

## Problem

Enrollment creates an Auth user via `handle_new_user` trigger (`on_auth_user_created` → `public.handle_new_user()` in `001_profiles.sql`). That row made `AuthContext` load `profiles` **before** `get_operational_station_device_context()`, treating the device JWT as a human `colaborador`.

## Fix order (remote)

1. **Merge Draft PR #10** (this hotfix) after review.
2. **Deploy Edge** `operational-station-enroll` (app_metadata + profile cleanup before session).
3. **Apply SQL** `196_fix_operational_station_technical_identity.sql` in Supabase SQL Editor.
4. Run `diagnose_operational_station_technical_identity_preflight_196.sql` **before** 196; postflight after.
5. Run `196_test_operational_station_technical_identity.sql` (BEGIN/ROLLBACK self-check + post-apply on prod).
6. **Clear device local session** (already done) — do **not** re-enroll until steps 2–3 succeed.
7. Re-enroll station device once; confirm Network calls `get_operational_station_device_context` and `/station/cash` loads PIN shell.
8. Leave `operational-station-access` flag, PIN, assignments, and Caja Principal unchanged unless a separate change is approved.

## AuthContext (new order)

1. Session present → if `isOperationalStationDeviceSessionCandidate` (`app_metadata` then `user_metadata`) → RPC `get_operational_station_device_context`.
2. RPC `active` → `stationDeviceContext` set; `profile`/`user` null; human `isAuthenticated` false.
3. Candidate but RPC error/inactive → deny; **no** `profiles` query.
4. Otherwise → existing human `profiles` flow unchanged.

## Edge compensation

After `auth.admin.createUser`, `removeAutogeneratedTechnicalProfile` deletes `profiles.id = authUserId` only when Auth metadata marks technical device **and** `device_id` matches enrollment payload. On failure: `deleteUser`, `fail_station_device_enrollment`, no tokens returned.

## 196 eligibility (no PII in ops)

Rows targeted when **all** hold:

- `profiles.id = operational_station_devices.auth_user_id` (non-null).
- Auth user has `operational_station_device = true` in `raw_app_meta_data` or `raw_user_meta_data` (when `auth.users` readable).
- **Not** blocked by: `employee_id`, `operational_credentials`, `operational_station_assignments`, `operational_operator_sessions`, or `pos_orders.owner_profile_id`.

Preflight raises `196_preflight_blocked` if any device-linked profile has those human/financial ties.
